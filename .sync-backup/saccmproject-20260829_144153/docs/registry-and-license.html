1. ภาพรวมสถาปัตยกรรม 3 ชั้น

SACCM แยกบริการ license ออกจาก Online API อย่างชัดเจน — ข้อมูลการเงินไม่เก็บใน Registry

ชั้น ที่อยู่ พอร์ต (ค่าเริ่มต้น) หน้าที่
ทดลองใช้บนเครื่อง forntend/lib/features/license/embedded_trial_license.dart — kEmbeddedTrialDays = 90 — วันแรกไม่ต้องลงทะเบียน Registry
Registry registry-backend/ 3802 keygen, activate, log, รายการเครื่อง, trial anchor
Online API backend/ 3801 ข้อมูลการเงิน, sync, JWT login — ไม่มี license 
[Registry :3802]  DB: saccm_registry
    │ activate → log
    │ provision (online เท่านั้น) ──┐
    ▼                                ▼
[Online API :3801]  saccm_master + saccm_<school_code>

[แอปโรงเรียน] → Registry (license/trial) + Online API (sync/login)

เอกสารที่เกี่ยวข้อง: release/docs/KEYGEN-DESIGN.md, docs/PRODUCT-TIERS.md, release/README-DISTRIBUTION.md

2. registry-backend ทำงานอย่างไร

2.1 Entry point

ไฟล์: registry-backend/index.js

  1. ตรวจ config (validateRegistryRuntimeConfig)
  2. สร้าง Express + HTTP hardening (helmet, CORS, rate limit)
  3. สร้าง DB saccm_registry ถ้ายังไม่มี แล้วรัน migration อัตโนมัติ
  4. เปิดพอร์ต 3802 ที่ path /registryapi

2.2 ฐานข้อมูล (แยกจาก backend)

ตารางหน้าที่
school_licensehash รหัส (bcrypt), สถานะ, offline/online, วันหมดอายุ
school_deviceเครื่องที่ activate (จำกัด max_devices default 3)
license_issue_logบันทึกตอน keygen
license_activation_logactivate สำเร็จ/ล้มเหลว, heartbeat
trial_registrationanchor วันเริ่มทดลองใช้ต่อ fingerprint

รหัสรูปแบบ SACC-XXXX-XXXX-XXXX — เก็บแค่ hash ไม่เก็บรหัสเต็ม (มี key_hint เช่น ...-AB12)

2.3 API Endpoints

สำหรับแอป (ไม่ต้อง admin secret)

MethodPathหน้าที่
GET/registryapihealth / ping
POST/registryapi/license/activateเปิดใช้งาน + ลงทะเบียนเครื่อง
POST/registryapi/license/validateตรวจรหัสก่อน activate
POST/registryapi/license/statusสถานะ license + รายการเครื่อง
POST/registryapi/license/heartbeatอัปเดต last_seen
POST/registryapi/license/tokenขอ JWT สำหรับ sync (online เท่านั้น)
POST/registryapi/trial/startเริ่ม/ดึง trial ต่อ fingerprint (90 วัน server-anchored)

สำหรับผู้ให้บริการ (header X-License-Admin-Secret)

MethodPathหน้าที่
POST/registryapi/license/admin/generateออกรหัสใหม่
GET/registryapi/license/admin/listรายการ license
GET/registryapi/license/admin/issue-logslog การออกรหัส
GET/registryapi/license/admin/activation-logslog การเปิดใช้งาน
POST/registryapi/license/admin/revokeยกเลิกรหัส

2.4 Flow activate (online)

Admin → Registry: keygen --name "โรงเรียน"
Registry → Admin: SACC-ABCD-...

App → Registry: POST /license/activate
Registry → ตรวจ hash, สถานะ, จำนวนเครื่อง
Registry → Online API: POST /internal/school/provision  (ครั้งแรก, online)
Online API → สร้าง school_tenant + DB saccm_xxx
Registry → Online API: POST /login/token
Registry → App: schoolCode, JWT, canSync=true
  • offline: ใช้งานออฟไลน์ได้ ไม่ provision DB
  • online: ครั้งแรกที่ activate จะ provision โรงเรียนบน Online API แล้วคืน JWT

2.5 การเชื่อม Online API

ไฟล์: registry-backend/src/services/online_client.js

  • Provision: POST {ONLINE_API_BASE}internal/school/provision + header X-Internal-Secret
  • Login token: POST {ONLINE_API_BASE}login/token + schoolCode

2.6 Config สำคัญ (.env)

ตัวแปรหมายเหตุ
DB_NAME=saccm_registryแยกจาก DB ของ backend
INTERNAL_API_SECRETต้องตรงกับ backend
LICENSE_ADMIN_SECRETadmin API / keygen ผ่าน HTTP
TRIAL_SIGNING_SECRETเซ็น payload trial
ONLINE_API_BASEเช่น http://127.0.0.1:3801/saccapi/

2.7 Keygen (CLI)

cd registry-backend
npm run keygen:offline -- --name "โรงเรียนบ้านตัวอย่าง"
npm run keygen:online -- --name "โรงเรียน ก." --days 365

3. แอป Flutter เรียก Registry

3.1 HTTP client

แอปเรียก Registry ผ่าน LicenseRemoteDataSource (Dio) — base URL จาก registryBase ใน forntend/lib/config.dart แยกจาก Online API (baseurl)

static const _defaultRegistryBase = String.fromEnvironment(
  'SACC_REGISTRY_BASE',
  defaultValue: 'https://ktdevelop.com/registryapi/',
);
สำคัญ: RuntimeConfig.loadFromPreferences() เปลี่ยนได้เฉพาะ SACC_API_BASE จากหน้าตั้งค่า — Registry URL ไม่เปลี่ยน runtime (bake ตอน compile)

3.2 ชั้นโค้ด

UI (LicenseActivationPage, LicenseGate, …)
    ↓
LicenseRemoteDataSource  ←→  Registry :3802/registryapi/
LicenseLocalDataSource   (schoolCode, deviceId, tier ในเครื่อง)
EmbeddedTrialLicense     (trial local + sync server)
LicenseMode              (snapshot สถานะแอป)

3.3 เมื่อไหร่เรียก Registry

จังหวะไฟล์หลักEndpoint

revalidate (online) license_mode.dart POST license/status

3.5 Trial anchor (Tier B)

DeviceFingerprint.get() สร้าง SHA256 จาก hardware/install id แล้วเรียก POST trial/start — ใช้วันหมดอายุที่ เร็วกว่า ระหว่าง local กับ server เสมอ

3.6 สิ่งที่แอปไม่เรียก Registry

  • Login ปกติ / sync ข้อมูลการเงิน → Online API (baseurl)
  • ทดลองใช้วันแรกแบบ offline → local เท่านั้น

4. MasterDataSyncService หลัง activate

4.1 เมื่อไหร่รัน

หลัง POST license/activate สำเร็จ — LicenseActivationPage เรียก sync เฉพาะแพ็กเกจ online (result.canSync == true)

แพ็กเกจ offline ข้าม sync ทั้งหมด แล้วไปหน้า login

Registry: activate → token, schoolCode, canSync=true
Local: saveActivation (JWT ใน SecureCredentialStore)
MasterDataSyncService.run() → Online API (ไม่ใช่ Registry)
→ SimpleLoginPage

4.2 เงื่อนไขใน run()

ไฟล์: forntend/lib/core/services/master_data_sync_service.dart

  1. LicenseMode.canSyncOnline() ต้องเป็น true
  2. มีเน็ต (NetworkInfoService.isConnected)
  3. Phase 1: BackupFullMirrorSync.runMastersOnly
  4. Phase 2: ดึงเมนูด้วย JWT (MenuRemoteDataSource.fetchAllRows)

4.3 Master tables ที่ดึง (Phase 1)

จาก Online API (SACC_API_BASE) — ไม่ดึงรายการธุรกรรม (income/expense/loan)

5. การตั้ง SACC_REGISTRY_BASE ตอน build Windows

5.1 Compile-time constant

SACC_REGISTRY_BASE ถูก bake เข้า binary ผ่าน --dart-define ตอน flutter build / flutter run

5.2 Protected build (dev/internal)

pwsh forntend\tool\build_windows_protected.ps1

pwsh forntend\tool\build_windows_protected.ps1 `
  -ApiBase "https://your-server.example.com/saccapi/" `
  -RegistryBase "https://your-server.example.com/registryapi/"

ผลลัพธ์: forntend\build\windows\x64\runner\Release\

5.3 Release แจกโรงเรียน

cd release\scripts
.\build-release.ps1 `
  -SchoolSlug "school-a" `
  -ApiBase "https://your-server.example.com" `
  -RegistryBase "https://your-server.example.com" `
  -Version "1.0.0+1"

สคริปต์ normalize URL เป็น /saccapi/ และ /registryapi/ แล้ว build ทั้ง Windows และ Android

5.4 Dev บนเครื่อง

cd forntend
flutter run -d windows `
  --dart-define=SACC_API_BASE=http://127.0.0.1:3801/saccapi/ `
  --dart-define=SACC_REGISTRY_BASE=http://127.0.0.1:3802/registryapi/

5.5 ความต่าง API vs Registry หลัง build

ค่าตั้งตอน buildเปลี่ยนในแอปได้?ใช้กับ
SACC_API_BASE--dart-defineได้ (Settings)sync, login, master data
SACC_REGISTRY_BASE--dart-defineไม่ได้activate, trial, heartbeat, token
ถ้า Registry กับ Online API อยู่คนละ host ต้องใส่ -RegistryBase แยกตอน build — ผู้ใช้แก้จากหน้าตั้งค่าในแอปไม่ได้
