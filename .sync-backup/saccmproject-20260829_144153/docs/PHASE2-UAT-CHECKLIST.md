# Phase 2 UAT Checklist

ใช้ checklist นี้กับข้อมูลโรงเรียนจริงหรือชุดข้อมูลจำลองที่แทนเคสจริง ก่อนสรุปว่าเฟส 2 พร้อมใช้งานหลายเครื่อง

---

## 1. Master / Sync Setup

- [ ] เปิดใช้งาน license และได้ server token จริง
- [ ] รัน full mirror แล้ว master data ครบ: `moneygroup`, `moneytype`, `incometype`, `budgetsource`
- [ ] ตรวจ OB-01..OB-13 และ DEP-GUAR / DEP-WHT แสดงถูกต้องในแอป
- [ ] เครื่องที่สอง sync แล้วเห็น master data ชุดเดียวกัน

---

## 2. Core Transaction Flow

- [ ] รับเงินงบประมาณด้วยเงินฝากธนาคาร แล้วรายงาน daily balance ช่องธนาคารเพิ่มถูกต้อง
- [ ] รับเงินนอกงบประมาณ OB-01 และ OB-09 แล้วทะเบียนนอกงบแยกหมวดถูกต้อง
- [ ] จ่ายเงินสดจากหมวดนอกงบประมาณ แล้วยอดเงินสดลดถูกต้อง
- [ ] จ่ายเช็ค แล้วทะเบียนจ่ายเช็คแสดง pending/cleared ถูกต้อง
- [ ] ยืมเงิน → คืนเงินยืม แล้วรายงานเงินยืมค้างเหลือยอดถูกต้อง
- [ ] รับเงินประกัน/ภาษีหัก ณ ที่จ่าย → settle แล้วสถานะและทะเบียนถูกต้อง

---

## 3. Daily Closing

- [ ] ปิดวันขณะออนไลน์ แล้ว server และ SQLite มี `daily_closing` วันเดียวกัน
- [ ] ปิดวันขณะออฟไลน์ แล้วแอปแสดงว่าปิดวันแล้วทันที
- [ ] กลับมาออนไลน์แล้ว pending sync หาย และ `daily_closing.synced = 1`
- [ ] พยายามปิดวันซ้ำ ต้องถูกบล็อก
- [ ] ถ้าเงินสดเกินวงเงินเก็บรักษา ต้องขึ้นคำเตือนและปิดวันไม่ได้

---

## 4. Bank Reconciliation

- [ ] บันทึก reason code กรณีเช็คค้างขึ้นเงิน
- [ ] บันทึก reason code ขณะออฟไลน์แล้วกลับมาออนไลน์ ต้อง sync สำเร็จ
- [ ] เปิดงบเทียบยอดธนาคารแล้วเห็นยอดเคลื่อนไหวตรงกับรายรับ/รายจ่าย

---

## 5. Reports / Forms

- [ ] รายงานเงินคงเหลือประจำวันตรงกับทะเบียนคุม
- [ ] รายงานรับ-จ่ายประจำปีตรงกับยอดรวมรายรับ/รายจ่าย
- [ ] ส่งออก CSV จากทะเบียนหลักได้
- [ ] สร้าง PDF บก.111, บค., บก.28, สัญญายืมเงิน, ทะเบียนเงินประกันได้
- [ ] Flutter Web ดาวน์โหลด PDF ได้จริง

---

## 6. Multi-Device

- [ ] เครื่อง A สร้างธุรกรรม offline แล้ว sync สำเร็จเมื่อออนไลน์
- [ ] เครื่อง B full mirror / digest sync แล้วเห็นรายการจากเครื่อง A
- [ ] เครื่อง B ไม่ทับ pending writes ของตัวเองหลัง full mirror
- [ ] token refresh ไม่ทำให้ sync ล้มระหว่างใช้งานนานกว่า 1 ชั่วโมง
